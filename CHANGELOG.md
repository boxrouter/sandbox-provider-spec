# Changelog

Notable changes to the specification and its tools. [GOVERNANCE.md](GOVERNANCE.md#versioning)
says what each kind of release may change.

## 0.5.142 — 2026-11-25

- New rule `provider-api/create-meets-stated-facts` (`provider-api.md` section 4): a provider does not refuse a `create` for an ask in its `resources` that the class's discovery states it meets. A router sends a class the asks it matched the class on, such as `extendable_lifetime: true` for a lifetime it renews, while the tester's rows ask only floors and the facts of their own claim, so a provider could pass every row and refuse every routed create. The new test `contract.create_meets_stated_facts` creates once with every yes-or-no resource fact (a boolean `resources` field of the request schema: `extendable_lifetime`, `long_running`, `size_is_ceiling`) that the class states `true`; a refusal as `unsupported` is the failure `stated_fact_refused`, and a class that states none of them reads `not_run` and does not count. Its step `create.stated_facts` is a driver subclass of its own (`v1/suite_driver_stated_facts.py`), so no existing row's check digest moves (0 of 291; 1 row added). The suite digest changes with the new row: `conformance/historical-suite-rules.json` keeps the prior shared suite (`sha256:d86dc50e…`, 291 tests) so every committed report stays recognized.

## 0.5.141 — 2026-11-25

- The tester runs `custom_images.provider_artifact` for a class that lists no image operation. The row's `image.prepare` of a `provider_artifact` borrows an image that the account already has and calls no provider operation, but the tester marked `image.prepare` unsupported wherever discovery did not claim it, so a provider that can create from its own artifacts but prepares no image could not prove `custom_images` `source: provider_artifact`. The tester's driver (`SetupRetryDriver.image_prepare`) now refuses every other source in that case, so every other row reads `unsupported` as before. No row's check digest moves (measured: 0 of 291).

The first public draft, format version 0.1 (`spec: sandbox-provider-spec/0.1`):

- The specification: a baseline every provider passes, 14 gates with 43 knobs, and facts
  about compute, time, place, network, hardware and environment.
- The declaration, request and run report formats, with JSON Schemas, the vocabulary as a
  catalog, and registries of region and GPU model identifiers.
- Deterministic matching rules, a reference matcher, and test vectors for independent
  implementations.
- A conformance suite of 181 tests, a runner with drivers for six providers, and the
  Docker Engine reference declaration with its run reports.
- The `sandbox-provider-spec` command: `check` validates requests, declarations and reports;
  `match` says which declarations satisfy a request and why the others do not; `run` produces
  evidence against a provider.
- Example requests for common workloads.
